# 自适应分块与结构化分块对照

本实验检验自然段合并对科研文本证据检索的影响，使用现有 BGE、BM25、FAISS 和 RRF，不增加生成模型调用。

## 数据与控制变量

使用官方 QASPER Validation 的全部 281 篇论文建立索引，1005 道问题中，841 道具有可唯一对齐的文本证据，来自 274 篇论文。排除无答案、无文本证据或无法唯一映射的问题，规则与 [主实验](benchmark.md) 相同。

| 条件 | 两组共同配置 |
|---|---|
| Embedding | BAAI/bge-small-en-v1.5，384 维，归一化，内积检索 |
| 块长度上限 | 480 个 BGE Token（含特殊 Token），同时不超过 1200 字符 |
| Overlap | 0 |
| 候选 | BM25、Dense 各最多 50 个；RRF 常数 60、等权 |
| 检索范围 | 单篇论文内，统计 K=1、5、10 |
| 证据组织 | Hybrid 前五；Anchor-First 使用相同前五、邻段窗口 1 |
| 上下文上限 | 7400 字符，含引用头信息，不截断完整 Chunk |
| 统计 | 问题宏平均；按论文聚类配对 Bootstrap，2000 次，种子 42 |
| 运行 | 本地 CPU、8 线程、离线模型与数据缓存 |

唯一修改的分块配置是 strategy：

- **adaptive**：同章节、同页的相邻普通段落或列表可以合并；待合并两侧均不超过 240 Token，合并后仍须满足 480 Token 和 1200 字符上限。
- **structure**：保留每个原始段落边界，不合并相邻段落；过长段落采用与 adaptive 相同的段落、句子、词边界优先切分规则。

两者均保留标题边界及原文字符跨度，不把标题、表格、公式或代码与普通段落合并。本数据使用 QASPER 已提供的章节和文本段落，结果不衡量扫描 PDF 的 OCR 或版面识别能力。

## 口径与采用规则

主指标为 Anchor-First 上下文的完整段落 Recall：对每题计算完整覆盖的 Gold 段落占 Gold 并集的比例。推荐 structure 进入后续验证需要同时满足：其相对 adaptive 的该指标配对 95% 区间下界大于 0，且 Hybrid Hit@5、MRR@5 均不下降。协议在评分前保存，本实验不自动切换应用默认配置。

完整段落覆盖要求原文字符跨度连续覆盖整个段落；普通段落 Recall 只要求来源相交。全部 Gold 完整覆盖要求每段 Gold 均完整进入上下文。Evidence F1 采用多份参考中的最大段落集合 F1，定义见 [主实验](benchmark.md)。

不同分块方法会改变相关 Chunk 数量，因此块级 Precision、nDCG 作为描述性指标保留，判断时同时看固定来源段落的覆盖。相同字符上限也不等于相同实际输入量，需连同实际字符数、Chunk 数量和 BGE 参考 Token 阅读。

### 配对差异与结论

下表为 **adaptive − structure**，正数表示自适应分块较高；公开 JSON 保存相反方向的原始差值。百分比指标的差异单位为百分点。

| 指标 | 平均差异 | 按论文聚类的 95% 区间 |
|---|---:|---:|
| Hybrid Hit@5 | 5.47 | [3.14, 7.98] |
| Hybrid 来源 Recall@5 | 7.85 | [5.88, 10.02] |
| Hybrid MRR@5 | 0.0455 | [0.0288, 0.0628] |
| Anchor-First 完整段落 Recall（主指标） | 2.66 | [0.64, 4.79] |

逐题对照：两组同时命中 544 题，仅结构化命中 30 题，仅自适应命中 76 题，两组均未命中 191 题。

**采用结论：保留 adaptive。** 结构化分块未满足主指标及 Hit/MRR 的采用条件。它在前五 Evidence F1 上较高，体现证据段落集合更精简与来源覆盖之间的取舍；不能仅据少量段落角色混杂的案例，推断全面取消短段合并会提升总体效果。

两种策略均完整保留原始文本。不同分块粒度会同时影响候选竞争、固定 K 的来源范围和现有邻段扩展，本结果是这套固定检索流程下的策略对照，不将差异全部归因于单一语义现象。

### 索引与本机耗时

| 分块 | Chunk 数 | 合并多个原段的 Chunk | 原始 float32 向量 MiB | 分块秒数 | 候选生成与融合均值 / P50 / P95 ms |
|---|---:|---:|---:|---:|---|
| 自适应 | 11,956 | 3,155 | 17.51 | 12.80 | 10.80 / 10.11 / 14.22 |
| 结构化 | 17,588 | 0 | 25.76 | 9.04 | 11.12 / 10.45 / 14.59 |

自适应组 281/281 篇复用已校验向量，恢复并构建检索器合计 4.26 秒；结构化组 0/281 命中缓存，首次编码及索引准备合计 472.58 秒。缓存状态不同，不据此声称冷构建加速。原始向量体积不含 FAISS、BM25、元数据及 Python 对象开销。

候选生成与融合耗时包含真实 BGE 问题编码、BM25、FAISS 和 RRF；同一策略的三路质量评分共享一次候选生成。它不是三种方法各自的独立 API 延迟，也不是完整问答延迟。BGE 参考 Token 只描述证据长度，不是生成模型的账单用量。

全流程本次耗时 542.19 秒，生成 API 调用 0 次。数值为本机一次运行观测。

```powershell
.\.venv\Scripts\python.exe scripts/compare_chunking.py data/fusion_comparisons/your_validation_run --threads 8
.\.venv\Scripts\python.exe scripts/export_chunking_comparison.py data/chunking_comparisons/your_chunking_run
```

可通过 `--dataset-file` 指定官方 Arrow 或 Parquet。比较脚本核对源文件、模型配置和问题集合指纹，并逐题复现 adaptive 的 Dense、Hybrid 前十排名及 @5 指标。所有原始文本块（含非 Gold 内容与标题）均验证原文字符保留；不同策略使用独立版本与缓存键。

运行目录保存冻结配置、代码指纹、排除清单、逐题排名、逐篇成本和结果校验和。导出器重算指标与采用规则，核对两组全部 Chunk 的长度预算、向量尺寸和计数，并拒绝覆盖已有公开结果。公开文件只包含标识、配置和数值。

## 适用范围

本对照由 [Test 案例阅读](case_studies.md) 提出假设，属于 Validation 上的探索性分析；保留原 Test Baseline，不把同一 Test 的再次分析称为独立盲测。来源覆盖不能直接作为生成回答正确率。耗时是本机一次运行观测，缓存恢复与首次编码分别报告。
